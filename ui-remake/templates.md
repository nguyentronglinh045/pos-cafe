# Mẫu cho task UI từ Stitch

Dùng cùng [quy trình](README.md), [Palette A v1](palette.md), [cách đo](measurement.md) và [SPEC-STANDARD](https://github.com/nguyentronglinh045/pos-cafe/blob/docs/openspec/SPEC-STANDARD.md). Sao chép phần cần thiết vào hồ sơ task/change trên `docs`; không tạo một bản chuẩn thứ hai. Trường chưa có nguồn ghi `CHƯA XÁC MINH`, chưa chạy ghi `NOT_RUN`, quyết định chưa chốt ghi `ĐỀ XUẤT`.

<a id="tiep-nhan"></a>
## 1. Tiếp nhận và giới hạn slice

```markdown
# <task-id> — <slice>
Ngày / người thực hiện: ...
Mục tiêu quan sát được: ...
Nguồn ủy quyền (ngày, lời giao việc/link quyết định): ...
Được làm: ...
Ngoài phạm vi / phần hoãn và dependency: ...
Code worktree / branch / HEAD / dirty fingerprint: ...
Docs worktree / branch / HEAD / dirty fingerprint: ...
Spec/change / bàn giao trước: ...

| Reference/state | Màn hình hiện có | Cách tới + selector ổn định | Actor/quyền | Fixture | Code file:dòng |
| --- | --- | --- | --- | --- | --- |
| ... | ... | ... | ... | ... | ... |

| Câu hỏi chặn | Tình huống/bằng chứng | Phương án + đánh đổi | Khuyến nghị | Chặn phần nào |
| --- | --- | --- | --- | --- |
| Q-01 | ... | ... | ... | ... |

Không có đối ứng trong sản phẩm: ...; xử lý: ngoài phạm vi / xin quyết định riêng.
```

Mỗi state cần chỉ rõ normal/loading/empty/error/disabled/modal và state sau thao tác nào thuộc slice; không nhận một ảnh là coverage cho cả màn hình. Quyền và hành vi hiện tại phải có nguồn code, không suy từ Stitch.

## 2. Nguồn, chuẩn hóa và phê duyệt reference

```markdown
## Reference <id>@<version>
URL/source owner: ...
Thời điểm lấy / cách truy cập / quyền chia sẻ: ...
Source/assets xuất được: ...; phần không lấy được và giới hạn: ...
Raw path / SHA-256 manifest: ...
Raw state / viewport CSS px / DPR / browser: ...
Font gốc và căn cứ (source / computed style / chỉ suy đoán): ...
Recipe dựng nguồn local + khóa dữ liệu/animation/thời gian: ...

| Vai trò/thành phần gốc | Token Palette A v1 / Be Vietnam Pro | Thay đổi bố cục dự kiến | Căn cứ / cách kiểm |
| --- | --- | --- | --- |
| ... | ... | ... | ... |

Normalized source/capture path / hash / version: ...
Viewport/state được reference này bao phủ: ...
Phần chưa biết do chỉ có ảnh: ...; cách xử lý đã chốt: ...
Sai khác tham chiếu: DEV-...
Chủ dự án duyệt (ngày, nội dung, nguồn xác nhận): ...
Trạng thái: ĐỀ XUẤT / ĐÃ DUYỆT / ĐÃ THAY THẾ BỞI ...
```

Giữ raw và normalized độc lập. Không hue-rotate ảnh; không tự chụp actual thành reference; implementation golden là hồ sơ hồi quy riêng sau nghiệm thu. Thay reference tạo version mới, giữ bản cũ và lý do.

## 3. Ma trận viewport, state và hợp đồng đo

```markdown

Breakpoint theo nội dung và căn cứ đo: ...

| Case ID | State / fixture | W×H CSS px | DPR | Reference id@version hoặc KHÔNG CÓ | Kiểu kiểm | Thao tác/expected |
| --- | --- | --- | --- | --- | --- | --- |
| MIN | ... | 568×320 | ... | ... | fidelity + responsive / chỉ responsive | ... |
| LOW | ... | <ngang thấp, số cụ thể> | ... | ... | ... | ... |
| PHONE | ... | 844×390 | ... | ... | ... | ... |
| TABLET-L | ... | 1024×600 | ... | ... | ... | ... |
| TABLET-H | ... | 1024×768 | ... | ... | ... | ... |
| DESKTOP | ... | 1440×900 | ... | ... | ... | ... |
| FULLHD | ... | 1920×1080 | ... | ... | ... | ... |
| ULTRAWIDE | ... | <số cụ thể> | ... | ... | ... | ... |
| BP-n | ... | <b−1, b, b+1; height cụ thể> | ... | ... | ... | ... |

Sweep bổ sung (khoảng, bước, lý do; không thay ma trận bắt buộc): ...
Nội dung biên (tên dài/danh sách dài/giá trị lớn/empty/error): ...
Touch/keyboard/focus, CTA, scroll, modal/drawer, sàn sau scale: ...
Giới hạn thiết bị thật chưa kiểm: ...
```

```markdown
## Cấu hình đo đã chốt
Config path/hash và phiên bản runner: ...
Reference URL local / actual URL local: ...
State readiness selector + thứ tự actions click/fill/waitFor: ...
Anchors: reference selector → actual selector → tolerance CSS px: ...
Pixel channel threshold / max diff ratio và lý do calibration: ...
Critical regions (selector/vùng, ngưỡng riêng, lý do): ...
Vùng động loại trừ (quyết định, phạm vi; không che lỗi): ...
Chủ dự án chốt reference/ngưỡng/deviations (nguồn): ...
Không có reference cho case nào: ... → chỉ kiểm responsive contract.
```

Dùng schema/example thật của runner theo measurement.md khi viết JSON, không coi bảng này là schema executable. Một bộ cấu hình phải có expected rõ trước khi chụp actual; không chỉnh ngưỡng theo kết quả muốn đạt.

<a id="sai-khac"></a>
## 4. Quyết định và sai khác được duyệt

```markdown
### DEV-<nn> — <nội dung>
Ngày / trạng thái: ... / ĐỀ XUẤT | ĐÃ DUYỆT | ĐÃ THAY THẾ
Vấn đề + bằng chứng raw/source/code: ...
Reference/state/viewport/vùng bị ảnh hưởng: ...
Phương án thật sự đã cân nhắc + đánh đổi: ...
Lựa chọn / lý do / hệ quả: ...
Expected mới và cách đo cụ thể: ...
Giữ nguyên nghiệp vụ/quyền/dữ liệu bằng kiểm nào: ...
Người quyết định / nguồn ủy quyền hoặc xác nhận / ngày: ...
Thay thế quyết định nào / được thay thế bởi: ...
Tác động config, reference version, spec và test cần cập nhật: ...
```

Phân biệt quyết định kỹ thuật agent tự chọn trong phạm vi được giao với quyết định chủ dự án phê duyệt. Thay đổi nghiệp vụ/quyền/backend/màn hình mới cần scope riêng; không ghi thành deviation thẩm mỹ.

## 5. Báo cáo bằng chứng và nghiệm thu

```markdown
# Kết quả <task-id> — <candidate-id>
Ngày / người chạy: ...
Code commit sạch hoặc baseline + fingerprint + snapshot/patch đầy đủ: ...
Docs candidate / manifest: ...
Reference raw/normalized version/hash + quyết định duyệt: ...
Môi trường/backend/schema/fixture (thật, mock hay tổng hợp): ...
Recipe dựng và chạy lại / điều kiện có sẵn: ...

| Gate | Bắt buộc | Lệnh + cwd + thời điểm | Exit | Tổng/đã chạy/skip/fail | Kết quả | Artifact + giới hạn |
| --- | --- | --- | --- | --- | --- | --- |
| metrics unit + runner selftest | Có | ... | ... | ... | PASS/FAIL/NOT_RUN/BLOCKED | Fixture tổng hợp; không nghiệm thu app |
| calibration | Có | ... | ... | ... | ... | ... |
| capture từng state/viewport | Có | ... | ... | ... | ... | Không đồng nghĩa comparison đạt |
| fidelity (chỉ case có reference) | ... | ... | ... | ... | ... | expected/actual/diff/overlay + anchors/critical regions |
| responsive contract | Có | ... | ... | ... | ... | Ma trận/sweep + touch/focus/scroll/CTA |
| npm run build | Khi đổi app | ... | ... | ... | ... | ... |
| npm test | Khi đổi app | ... | ... | ... | ... | ... |
| npm run smoke | Khi đổi app | ... | ... | ... | ... | Mock không chứng minh production |
| ui-audit:selftest | Khi đổi UI app | ... | ... | ... | ... | Phải đúng 23 findings + selftest OK |
| ui-audit + xem report/ảnh | Khi đổi UI app | ... | ... | ... | ... | Thiếu công cụ là NOT_RUN, chặn nghiệm thu |
| test nghiệp vụ/quyền bổ sung theo spec | ... | ... | ... | ... | ... | ... |

| Finding | State/viewport/selector/vùng | Đo được/expected | Lỗi thật / false positive + lý do | Chặn? | Sửa/kiểm lại/evidence |
| --- | --- | --- | --- | --- | --- |
| ... | ... | ... | ... | ... | ... |

Các case không có reference: ...; kết luận giới hạn ở responsive contract.
Gate chưa chạy/blocker và tác động nghiệm thu: ...
Không có thay đổi source sau bằng chứng / delta đã chạy lại: ...
```

```markdown
## Review và trạng thái bàn giao
| Reviewer độc lập | Trọng tâm | Candidate/delta | Đã kiểm/chưa kiểm | Findings chặn + xử lý | Verdict + nguồn |
| --- | --- | --- | --- | --- | --- |
| R1 | Phạm vi/reference/quyền/tiêu chí | ... | ... | ... | APPROVE/CHANGES_REQUESTED/BLOCKED |
| R2 | Phép đo/provenance/tái hiện/phản ví dụ | ... | ... | ... | APPROVE/CHANGES_REQUESTED/BLOCKED |

Quy trình/công cụ đóng task: cả hai reviewer bắt buộc APPROVE candidate cuối.
Slice app: áp dụng số reviewer theo AGENTS, không giảm gate hiện hành.
Hiện thực: ...; kiểm chứng: ...; nghiệm thu chủ dự án (nguồn): ...
Đã push (branch/commit/remote): ...; merge: ...; deploy: ...
Walkthrough code/test: đã đề nghị / đã thực hiện / đang chờ; nguồn phản hồi: ...
Phạm vi còn lại / người tiếp tục / bước tiếp theo / ủy quyền còn hiệu lực: ...
```

Exit 0 không đủ xác nhận hết lỗi UI. Giữ warning overflow/contrast/tiny target trong bảng phân loại; không tự `ui-audit:update`. Tách lỗi capture, lỗi fidelity, responsive, rendered audit và nghiệp vụ. Không nhận kết quả fixture tổng hợp thành kết quả app.

## 6. Ngân sách và cleanup tại checkpoint

```markdown
Ổ thực: C (runtime/cache/...) ...; D (workspace/artifacts/...) ...
Trước chạy / checkpoint / sau chạy: C trống ... GiB; D trống ... GiB.
Tăng tổng task so với đầu: ... GiB (trần vận hành 20 GiB, giữ trống ≥30 GiB).
Pilot: evidence dự kiến ... ≤0,5 GiB; tăng đỉnh ... ≤1 GiB; số đo thực: ...
Công cụ/browser có sẵn và nguồn xác minh: ...
Nếu cài: tên/mục đích/nơi cài/ổ thực/tải về/tăng sau cài/đỉnh gồm cache/căn cứ: ...
Nếu bất kỳ ước tính hoặc tổng lượt cài >1 GB: LỚN HƠN 1 GB — ...
Không biết mức tăng tối đa/không đủ dự trữ: dừng phần ghi ..., báo ...
Môi trường nặng duy nhất đang dùng / process đã đóng: ...
Evidence cần giữ và recipe: ...

Đề xuất dọn (chưa xóa khi chưa có phép):
| Đường dẫn tuyệt đối + identity | Loại/số lượng | Logical size / chiếm ổ thực | Vì sao tái tạo được | Tác động khi xóa |
| --- | --- | --- | --- | --- |
| ... | ... | ... | ... | ... |

Nguồn cho phép dọn đúng nhóm/phương pháp (hoặc ĐANG CHỜ): ...
Đường dẫn đã xác minh trong phạm vi + process đã nhả dữ liệu: ...
Sau xóa: C/D trống ...; dung lượng thực thu hồi ...; phần giữ lại ...
```

Không coi dừng process, rename/move cùng ổ hoặc Recycle Bin là đã thu hồi dung lượng. Không prune toàn máy, không dọn raw người dùng/đầu ra cuối/bằng chứng bắt buộc như temp.
